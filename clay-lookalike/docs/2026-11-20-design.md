# Clay Lookalike — design (2026-11-20)

## Intent
A demo that shows what precomputed embeddings make possible: click a few
things on an aerial map of San Francisco, and every chip that looks like them
lights up. No model runs; it is nearest-neighbour search over the Clay v1.5
NAIP embeddings published on Source Cooperative.

## Goals / non-goals / anti-goals
- Goals: instant results over SF; several positives and negatives; visual
  proof (thumbnails of the best matches); first-run download that the user
  starts and can watch.
- Non-goals: training a classifier, other states or years, exact 2020 NAIP as
  the basemap.
- Anti-goals: anything needing a server, API key or GPU; a slow first query.

## Constraints
- fused-render app in `showcase/clay-lookalike/` (index.html + .py, no server);
  runPython calls are capped at 60 s, so the download runs as a tracked job.
- Data: `https://data.source.coop/clay/clay-v1-5-naip-2/ca/2020/60cm/rgbir_cog/37122/`,
  the scenes of NAIP quads 12–14 and 20–22 (SF city). Chips are 256 px at
  60 cm (~154 m); embeddings are 1024-d; ~36k chips, ~150 MB of parquet.
- Basemap: Esri World Imagery tiles (attribution shown). NAIP tile services 404.
- Cache: the app's own `.fused/cache/` (fused-render convention: rebuildable, gitignored, never exported).

## Approaches
- A. Fixed SF dataset loaded once; numpy cosine search per query. **Picked.**
- B. Load any California area on demand from the map view. More useful, more
  moving parts; deferred.
- C. Fused canvas on fused.io. Shareable, but needs data on S3 and a canvas
  UI; not how the apps in this folder are built.

## Decided
- Page: deck.gl (standalone bundle) with a TileLayer basemap and a
  PolygonLayer of chip squares. Click = toggle positive, shift-click = toggle
  negative; the query reruns on every change. Chips are coloured by score;
  a slider sets how many matches are shown. A side strip shows the top
  matches as thumbnails cropped client-side from z17 basemap tiles; clicking
  one flies the map there.
- Python (`lookalike.py`): `status`, `download` (job: fetch each scene
  parquet, write `emb.npy` float32 L2-normalised, `bounds.npy`, `meta.json`),
  `chips` (bounds for the page), `query(pos, neg, k)`.
- Score = max cosine to any positive minus max cosine to any negative, so two
  unrelated positives both work (a centroid would not).

## Left to the builder
Colour ramp, default match count, thumbnail size, how scene downloads are
split to stay under the per-call limit, light/dark handling.
